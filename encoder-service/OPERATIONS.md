# 私网 NVENC 新闻导出服务

本目录只实现编码服务。部署前按主项目要求备份和审批，不会自动修改或重启线上服务。

- 3060 节点已只读核验 `/usr/bin/ffmpeg` 的 `h264_nvenc`，并完成200毫秒合成画面的无文件编码能力检查；真实新闻的性能及音画边界需要部署验收，不能由此宣称加速倍数。
- 建议 GPU 节点 `.30` 建独立非 root 用户 `brm-news-encoder`、独立 venv、工作目录 `/opt/brm-news-encoder`，给用户 video/render 设备访问权限。systemd 模板仅监听私网8092，防火墙只允许媒体节点 `.25`；不可通过公网代理暴露编码接口。
- 在服务器本地生成专用不少于24字符的 `ENCODER_API_KEY`，放入 root 600 的 `private.env`；`ENCODER_ROOT=/data/brm-news-encoder`，目录归编码用户所有且700。不要复用、显示或提交 ASR 密钥。
- `ENCODER_ALLOWED_HOSTS=172.16.28.25,172.16.28.30,127.0.0.1` 限定客户端地址（必须同时通过专用Bearer鉴权）；默认只允许回环地址。不要配置公网反向代理或信任任意转发头。
- 媒体服务配置 `NEWS_ENCODER_URL=http://172.16.28.30:8092` 与 `NEWS_ENCODER_KEY`；Compose 显式传入此配置，生产文件需局部合并，不能覆盖整个 `.env`/Compose。配置为空保持 CPU 兼容；配置后连接或硬件失败明确报错，不偷偷退回慢速CPU。
- 一任务传一次整期原文件，HTTP请求流式读写；不重复按片段传整期，不建立共享挂载，不加载整期到内存。仅视频走 NVENC；音频无需 GPU，仍在媒体节点 AAC 导出。
- 媒体全局最多2个识别/导出任务、每员工1个未完成任务保持不变。GPU编码线程池最多2个任务，单个任务各片段串行；GPU服务合计最多4个未完成请求（包含待传输、传输、排队与编码）。只开1个uvicorn进程，禁止多进程把并发倍增。ASR独立并发1。
- 原文件上限8GB，GPU缓存上限32GB，保留4GB空间；完成/失败后立即删除服务自己的源文件，结果保留1小时，并在后续请求时回收，不是全局定时清理。媒体回传后保留员工下载24小时，原录制不改动。
- GPU仍执行原来的毫秒精确 seek + 重编码（H264 NVENC p4/CQ20、AAC128k），不使用关键帧粗切；媒体回传会核验大小非空及片段时长差不超过250毫秒，再生成 ZIP。
- 进度按片段时长加权：1%文件传输阶段，10–85% GPU编码、85–90%结果回传、90%打包、完成才100%。CPU兼容也从FFmpeg out_time_us更新条内进度。上传和ZIP暂显示阶段文本，不伪造剩余时间。
- 进程重启将未完成GPU任务标为失败，不自动重复编码；媒体任务失败需重新提交。临时输出、服务凭据、输入路径不向浏览器返回。关闭PC窗口不会停止任务。
- 生产验收：先用短片段核验首帧、首字和音画同步、Range与ZIP，再比较整期全部条目的 CPU/GPU耗时（包含传输和打包），并测2任务与ASR同时运行的显存/CPU/磁盘峰值。确认后才考虑增加并发或硬件。
